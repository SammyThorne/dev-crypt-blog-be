# Dev Crypt Blog — Backend

Go + [Gin](https://gin-gonic.com/) API for the dev-crypt blog, with a Swagger UI generated by
[swaggo](https://github.com/swaggo/swag). It serves blog posts, comments, and Firebase-backed
role checks against a PostgreSQL database.

## Layout

```
cmd/server/          entrypoint: config, DB pool, HTTP(S) listener, graceful shutdown
internal/config/     environment configuration
internal/db/         pgx connection pool
internal/models/     request/response payloads
internal/auth/       Firebase token verification, role lookup, gin middleware
internal/handlers/   endpoint implementations
internal/router/     middleware + route wiring
docs/                swaggo-generated spec (committed; regenerate with `make swag`)
migration.sql        database schema
```

## Running

```bash
make build                                   # -> ./server
USE_TLS=false make run  # run from source
```

Swagger UI: `http://localhost:8081/swagger/index.html`.

Regenerate the spec after changing any handler annotation:

```bash
make swag-install   # once
make swag
```

## API

All endpoints are documented in the Swagger UI. Authenticated routes expect a Firebase ID token as
`Authorization: Bearer <token>`.

| Method | Path | Auth |
| --- | --- | --- |
| `GET` | `/` | none — echoes `User-Agent`, useful as a liveness check |
| `GET` | `/blogs.json` | none — static file with `ETag`/`If-None-Match` (replaces the old `server.py`) |
| `GET` | `/posts` | none |
| `POST` | `/posts` | `admin` or `writer` |
| `PUT` | `/posts/:postId` | `admin` (any post) or `writer` (own posts) |
| `DELETE` | `/posts/:postId` | `admin` (any post) or `writer` (own posts) |
| `GET` | `/posts/:postId/comments?offset=&limit=` | none |
| `POST` | `/comments` | any signed-in user; token UID must match `newUserId` |
| `DELETE` | `/comments/:commentId` | `admin` or `moderator` |
| `POST` | `/users` | none |
| `GET` | `/users/me/roles` | any signed-in user |

### Wire format

The JSON field names (`pTitle`, `newCommentText`, …) are inherited from the previous Haskell
implementation, where Aeson derived them from the record selectors. They are preserved verbatim so
the existing frontend works unchanged. Error responses are **plain text**, matching the old
Servant behaviour that clients read with `res.text()`.

## Notes

- `Dockerfile` and the frontend's `docker-compose.yml` still target the old Haskell build and need
  updating separately.
- Token verification calls Google's Identity Toolkit on every authenticated request. Verifying the
  JWT locally against Google's public certs would remove that round-trip.
